# 精读笔记（papers）

> 单篇论文深度精读笔记。触发方式：对话说「精读 X」或从 reading-list.md 队列消化。

## 笔记模板

```markdown
---
论文: 标题
arxiv: 2610.xxxxx
日期: YYYY-MM-DD
子方向: kv-cache
状态: 精读完成 / 仅摘要 / 复现中
---

# 标题

## 背景与动机（解决什么问题，为什么难）
## 方法（核心思路 + 伪代码/示意）
## 实验（关键数字：吞吐/延迟/显存，对比基线）
## 复现要点
- 代码: 链接（有无开源）
- 数据集: ...
- 关键超参: ...
- 最小复现路径: ...
## 启发与局限
## 新学到的术语（同步到 glossary/terms.yaml）
```

## 追问处理规范（Q&A 节）

用户对精读笔记追问时（如「XX 是怎么实现的」「为什么不用 YY」），Agent：

1. **优先读本地缓存** `notes/papers/.fulltext/<arxiv-id>.txt`（精读时 WebFetch 的全文缓存，git 忽略）——避免重复抓网页、秒级响应、可反复查不同段落。
2. 缓存不存在则重新 WebFetch `https://arxiv.org/abs/<id>`，并把全文写入 `.fulltext/<id>.txt` 供后续追问。
3. 回答后把**有沉淀价值的 Q&A** 追加到笔记的 `## Q&A` 节（一问一答，注明出处章节），格式：
   ```markdown
   ## Q&A

   ### Q1（2026-10-10）：delayed-batching 的等待时长具体怎么推导？
   > 详见论文 §5.2 吞吐模型：……（基于全文第 5.2 节的回答）
   ```
4. 无沉淀价值的追问（纯澄清/闲聊）只对话回答，不写笔记。
5. 追问中暴露的新术语 → 同步 glossary/terms.yaml；暴露的笔记错误 → 直接修正笔记正文。
6. 若追问需要论文之外的补充（如对比其他论文），回答时注明来源（基于知识库其他笔记/外部检索）。

**体验目标**：用户只需自然语言提问（针对当前打开的笔记或最近精读的论文），Agent 自动定位论文与全文；答案尽量引用论文具体章节/图表/数字，可追溯。
