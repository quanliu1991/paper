# ALLOT：视频扩散注意力的稀疏预算该按「最终视频损伤」分配，不该按局部指标

> 原文：[abs](https://arxiv.org/abs/2610.29441)

## 背景与动机

视频扩散 Transformer（Wan/HunyuanVideo）的 3D 全注意力随 token 数平方膨胀——Wan2.1-14B 生成一条 720p 81 帧视频约 1 小时，注意力占一半以上时间。块稀疏注意力是标准解法：把 query/key 切块、挑重要的块算。但「**每层每步保留多少块**」（allocation）这个问题，现有工作要么用拍脑袋规则（前 10-30% 步保持稠密、第一层稠密），要么用局部指标（注意力质量、Hellinger 距离、单步输出误差）。

作者的两个测量发现把现有做法戳穿了：

1. **敏感度跨层差 154 倍且模型间不同**——前一两层的单步误差是中位层的 154 倍，但「哪层最敏感」每个模型不一样，「第一层稠密」的通用规则不可迁移
2. **局部指标与最终视频损伤排序不一致**——注意力图指标的排序跟最终视频误差对不上；单步误差更是严重低估早步的杀伤力（同配置稀疏早窗口 vs 晚窗口，最终 MSE 差几百倍，单步误差却几乎没差甚至反序）

第三个关键观察是救星：**敏感度排序跨输入稳定**（Spearman 0.80-1.00）——离线测一次，所有 prompt 复用。

## 方法

把每个（层, 步）对看成一个 cell，目标是延迟预算下最小化最终视频总损伤：

- **Cell probing（层内误差）**：只稀疏化一层、其余全稠密，测该步速度预测的 MSE——区分层与候选密度，每次测量只要一次前向
- **Trajectory calibration（跨步放大）**：把去噪步切成窗口，每个窗口全层稀疏跑完整生成，最终视频 MSE 除以窗口内 cell 误差总和得增益 w(s)——捕捉下游步骤对误差的放大/衰减（早步误差被后续步骤放大几百倍）
- **延迟表 + 求解器**：r(b) 用部署时的 kernel 实测（稀疏 kernel 只在交叉点密度以下才比稠密快，按 FLOPs 假设成本会高估收益）；Lagrangian 松弛 + 二分 λ，每个 cell 独立取最优密度，warm-up 长度、哪些层保持稠密、密度随步的衰减形状全部从解里涌现，不靠人工规则

推理时查表即可，换延迟预算只需 CPU 上 4 秒重解一张表。

## 实验

四个模型（Wan2.1-1.3B/14B、Wan2.2-A14B、HunyuanVideo 13B）× 六种选择策略（XAttention/SVOO/SVG2/SpargeAttn/Radial/mean-pooled top-k）：

- **vs 其他分配方法**（固定 XAttention 选择策略只换分配）：ALLOT 胜出全部对比方法 1.53-7.31 dB；等墙钟时间下 PSNR 25.37 vs default 18.14
- **嵌入官方管线**（只换 allocation 组件）：九个设置六胜三平，最好 +5.03 dB；HunyuanVideo+SVOO 提升 3.38 dB 同时加速比 1.75×→1.90×
- **消融**：trajectory calibration 是命门——w(s)≡1 直接掉 7.05 dB，恰好掉回 DiTFastAttn 贪心规则的水平（19.34 vs 19.38）；说明跨步放大校准就是全部秘密
- **标定成本**：每模型 6-23 GPU 小时一次性离线测量；4 个探测视频 + 8 个校准 prompt 就够（再加没收益）
- **鲁棒性**：换步数（30 步）、CFG 7.5、Euler 采样器都不用重测

## 复现要点

- 代码：论文未见开源链接（KlingAI Research 实习工作）
- 标定流程可复现：cell probe = 单层稀疏的一次前向 MSE（8 密度 × 9 噪声级网格）；trajectory gain = 10 个五步窗口、窗口密度 0.30 的全生成
- 求解器极简：λ 二分 + 每 cell 独立 argmin，CPU 4 秒——这个优化框架本身可以搬到任何「预算分配 + 可测敏感度」的问题上
- 评测协议值得学：保真度对着同 prompt 同 seed 的稠密参考测 PSNR/SSIM/LPIPS，胜负判据用配对 95% CI——比报绝对 VBench 分严谨

## 启发与局限

- 核心洞察「**离线标定的输出敏感度 + 实测延迟表**」与昨天 CALM（自回归视频生成的层-头合并校准）完全同构——两条线在 AR 与扩散两种视频生成范式上独立收敛到同一方法论，说明「局部指标不可信、输出敏感度跨输入稳定」是生成式推理调优的普遍规律
- 与 LLM 侧的 MOSAIC（10-17，逐层 KV 预算搜索）、BELT 的 learned rank allocation 也是同一思想家族：资源分配从统一规则走向「按输出损伤标定的非均匀分配」
- 局限：换选择策略要重测 cell probe（虽然 w(s) 跨策略相关性 0.99）；加性/层可分近似只能预测排序不能预测误差幅度；每模型 6-23 GPU 时的标定成本对小团队不算小

## 疑问清单

1. w(s) 跨层共享（可分性假设）在极端场景（首层即最敏感层）下误差多大？附录 E 的 oracle 诊断给了多接近的上界？
2. 敏感度排序对「分辨率/帧数」的稳定性如何——480p 标定的表能否直接用于 720p？（主表是分开测的，没给迁移数据）
3. 与 SpecKCast（10-21，频域 Kalman 跳步预测）能否叠加：一个省步数、一个省块数，正交性看起来很强
