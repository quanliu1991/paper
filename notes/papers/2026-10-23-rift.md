# RIFT：draft 模型的 KV 压缩——prefill 时选的 KV 会「过期」，生成中要刷新

> 原文：[abs](https://arxiv.org/abs/2610.31098)（NVIDIA）

## 背景与动机

投机解码用在长输出场景（推理链、agent 轨迹）最划算，但 draft 模型的 KV cache 也跟着输出线性膨胀——混合注意力模型哪怕只有 25% 的层用 full attention，长上下文下 KV 也能超过权重本身的体积。给 draft 压 KV 是自然思路，但现有方法几乎都是 **prefill 时一次性选好**（SnapKV 这类），论文指出这有个隐藏缺陷：**decode staleness（解码陈旧化）**——选好的 KV 会随着生成推进逐渐「过期」。

一个反直觉的实验：同样 8K 预算，纯滑动窗口（SWA，无脑保留最近 token）反而打赢了精挑细选的 SnapKV——随着生成推进，SnapKV 的接受长度掉 36.7%，SWA 反而涨 41%。注意力质量分析给出机制：生成早期 draft 的注意力 67% 落在 SnapKV 保留的位置上，生成后期只剩 25.4%；SWA 正好相反（43.5%→68.7%）——**注意力整体搬移到了新生成的推理文本上**，推理链本身就像一份「滚动更新的 prompt 摘要」。混合注意力架构（Qwen3.5 线性层、Nemotron Mamba 层）下这个效应更严重。

## 方法

RIFT（Recency–Importance Fusion and Training）一族三档，按实现复杂度递增：

- **RIFT-stat**：预算 B 按 ρ 比例切两半——一部分给 prefill 重要性选择（SnapKV 等），一部分给滑动窗口。ρ=0.5 最优，比纯 SnapKV 提升 37.8%。改动极小，任何 prefill 选择法都能套
- **RIFT-dyn**：每 Δ 步用近期 observation window 重新打分整个可用 KV（全量 KV 在 HBM 或 offload 内存里），刷新工作集。100K ISL 下保留 95.7% 全量 AL（RIFT-stat 只有 85.6%）
- **RIFT-ada**：自适应刷新——接受长度、熵、query drift 三个信号触发，比固定周期刷新少 2.03× 刷新次数（或同刷新次数 +0.122 AL）

第四板斧是**压缩感知训练**：训练时就给 draft 戴上「压缩眼镜」——dense 打分 pass 构建 sparse attention mask，LoRA 学生在 mask 下做 KD（CE + KL，teacher rollout 预计算），消除训练（全量 KV）与推理（压缩 KV）的错配。

## 实验

- SPEED-Bench 32K ISL、4× 压缩：Qwen3.5-4B（target 122B）保留 96% 全量 AL，Nemotron3.5-Lightning 自投机保留 97%；SnapKV 只有 63-67%
- **组合拳（RIFT-ada + 压缩训练）**：32K 输入 / 4K 输出 / 8K KV 预算下保留 **>98%** 全量接受长度
- 压缩训练在低预算 regime 收益最大：2K 预算 T=1 下 +16.19%（Qwen）/ +16.42%（Nemotron）；预算大到基线已 >95% 时收益收窄
- 跨家族 drafting（Llama3.2-1B/Qwen3.5-4B → DeepSeek-V4）也成立，tokenizer 对齐 + KD 适配
- RIFT-stat 是通用增强：套在 CriticalKV/Expected Attention/CurDKV 上全部显著提升

## 复现要点

- 代码未开源（NVIDIA 技术报告路线），但 RIFT-stat 只需改预算分配逻辑，可在任意 vLLM/SGLang fork 上验证
- 评测基准 SPEED-Bench（NVIDIA 自家，2026.08）+ AL（平均接受长度）指标，可直接对齐
- 压缩训练配方：Nemotron V2 post-training 数据集、10K 步、batch 64、每样本随机采样压缩比增强预算鲁棒性、ρ=0.25
- 局限明确：GPU-only 预算下外部 draft 本身跑不过 MTP/EAGLE 这类 tail-augmented drafter——RIFT 的定位是**存算分离/边缘辅助 serving**（draft 在 SRAM 受限加速器上跑，选分在 GPU 算、只传选中的 KV 块过去）

## 启发与局限

- decode staleness 与昨天 ALLOT 的 trajectory calibration 是同一家族的问题：**一次性决策在长生成中过期**——ALLOT 是稀疏分配、RIFT 是 KV 选择，都靠「过程中刷新」解决
- 「注意力搬到新生成的推理文本上」给 10-21 的 AKV（agent 轨迹里 tool response 滚动 drop）提供了机制解释：后半段轨迹确实更值得关注
- 刷新开销实测只占 draft decode 延迟 ≤6%，但 SRAM 加速器场景要重测
- 与 KV-CAT（compressibility training 前作）的差别：KV-CAT 学打分模型做持续预训练，RIFT 用现成注意力分数 + 后训练 KD，工程上轻得多
