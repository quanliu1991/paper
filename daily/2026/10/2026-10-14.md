## 🚀 推理 Infra（19 篇）

### 1. ⭐ DoSA: Dots Sparse Attention（upvotes: 59）
- **一句话**：稀疏注意力找 Top-K 还得全量打分，这篇证明了「排除一个候选不需要它的完整分数」
- **方法**：种子集定阈值下界 + 非负投影/残差联合上界构造排除证书，只对仍合格的候选做全量打分，精确选择不损失
- **结果**：indexer 比 SGLang 快 2.74×（vs LiteTopK 1.69×），GLM-5.2/DeepSeek-V3.2 端到端 TTFT 提速 1.94×/1.50×
- **链接**：[arXiv](https://arxiv.org/abs/2610.13990) · infra 相关性: 5/5 · 子方向: long-context-vlm

### 2. ⭐ BELT: BEhavior-Aligned Low-Rank KV Cache Compression（upvotes: 0）
- **一句话**：低秩压缩 KV cache 别盯着「K 压缩后像不像」，要盯「注意力分布对不对」——后者才有闭式解
- **方法**：key 侧目标改为注意力分布 KL（Taylor+Kronecker 展开成二次，闭式加权 SVD）；rank 用可微 top-k 全局学、硬预算部署
- **结果**：70% 压缩下 LongBench 超最强基线 23.3 分；叠 3-bit 量化总压缩 17.8× 只掉 1.9 分；decode 吞吐最高 3.3×
- **链接**：[arXiv](https://arxiv.org/abs/2610.17966) · infra 相关性: 5/5 · 子方向: kv-cache · 🔍 已精读

### 3. ⭐ RadixFlow: Filling Execution Bubbles in Prefix-Cached Hybrid LLM Serving（upvotes: 0）
- **一句话**：混合架构前缀缓存命中≠能跑——被阻塞的分支把整条队列堵死，让堵的人只堵自己就行
- **方法**：state-ready traversal 把全局扫描屏障变局部等待，独立分支继续填批；已集成 vLLM
- **结果**：五个混合模型平均延迟降 3-24%、轮次降 11-44%，复用率纹丝不动
- **链接**：[arXiv](https://arxiv.org/abs/2610.18143) · infra 相关性: 5/5 · 子方向: serving-system · 🔍 已精读

### 4. ⭐ SP²ec: Adaptive Self-Speculative Decoding for VLMs（upvotes: 0）
- **一句话**：VLM 投机解码的 draft 配置没有万能款，用 bandit 在线选
- **方法**：利用 self-speculative 方法的单峰吞吐模式，training-free bandit 最小化 wall-time regret（对应真实延迟而非接受率）
- **结果**：Qwen2.5-VL-7B / LLaVA-NeXT-Mistral-7B 上稳定超原方法至 11%
- **链接**：[arXiv](https://arxiv.org/abs/2610.18735) · infra 相关性: 5/5 · 子方向: speculative-decoding

### 5. ⭐ Virtual Head Attention（upvotes: 0）
- **一句话**：KV cache 大小、算力、质量的「不可能三角」用两个线性操作同时松绑
- **方法**：Q Premix 从减半物理 query head 恢复虚拟 head 多样性 + Linear Postmix 低秩融合；推理时折叠回标准 GQA-2，现有优化全兼容
- **结果**：四规模预训练全面超 GQA 基线，KV cache 较 GQA-8 降 4×
- **链接**：[arXiv](https://arxiv.org/abs/2610.17959) · infra 相关性: 5/5 · 子方向: kv-cache

### 6. ⭐ Stable Token-level Scheduling for Serverless LLM Inference（upvotes: 0）
- **一句话**：serverless 推理光顾 TTFT 不够，token 间延迟的稳定才是体验关键
- **方法**：TWP 用 ITL/队列深度反馈在 token 级（非 batch 级）闭环调节准入 + chunked prefill
- **结果**：P99 尾延迟显著降、ITL 波动最小，吞吐比 ServerlessLLM 高至 45%
- **链接**：[arXiv](https://arxiv.org/abs/2610.17689) · infra 相关性: 4/5 · 子方向: serving-system

### 7. ⭐ Quota-Based Aging for Prediction-Guided Scheduling（upvotes: 0）

### 8. ⭐ MultiAlloc: Budget-Aware Precision Allocation for KV Cache Quantization（upvotes: 0）

### 9. ⭐ AlignPred: Error-Controlled KV Cache Compression（upvotes: 0）
- **一句话**：长时 agent 的持久 KV 压缩做成「对齐+预测编码」codec，误差可控
- **方法**：正交变换对齐相关 head/layer 后做 token 间/跨 head 预测，残差在误差受限格子量化+熵编码，无学习 predictor
- **结果**：同等误差存储更省、解码快 1.6×+；SGLang HiCache 持久 KV 省 42-72%
- **链接**：[arXiv](https://arxiv.org/abs/2610.17970) · infra 相关性: 4/5 · 子方向: kv-cache

### 10. ⭐ ChampionKV: Head-Wise Adaptive Budget Allocation（upvotes: 0）
- **一句话**：KV 压缩的预算按 head 分——注意力散的 head 多给、集中的少给
- **方法**：观测窗口注意力最大分做集中度代理 + 异常 head 掩码 + 保底预算，即插即用 SnapKV/PyramidKV
- **结果**：Llama3.1-70B 紧预算下提升最大且显著；7B/8B 持平
- **链接**：[arXiv](https://arxiv.org/abs/2610.18026) · infra 相关性: 4/5 · 子方向: kv-cache

### 12. ⭐ SparPR: Runtime KV-Cache Recovery on Consumer Hardware（upvotes: 0）

## 📖 今日新词
- **Execution Bubble**（learning）：调度中本可被合法工作填上的空闲批位；混合架构下 head-of-line blocking 的产物
- **Hybrid LLM**（learning）：linear attention（Mamba2 等）与 full attention 交错的架构，KV cache 外还有 recurrent state 需要 prefix 复用时同步
- **State-ready Traversal**（learning）：扫描等待队列时只阻塞同轮依赖的消费者、继续检查后续就绪分支的调度规则
- **Behavior-Aligned Compression**（learning）：压缩目标盯最终行为（注意力分布/输出）而非中间量重建误差
- **Learned Rank Allocation**（learning）：跨层跨 head 学 rank 分配——软门控 top-k 训练 + 硬预算部署
- **Self-Speculative Decoding**（learning）：用目标模型自身的变体（跳层/稀疏/量化）做 drafter 的投机解码，免训独立小模型
- **Behavior Policy Mismatch**（learning）：RL 中采样策略与被优化策略不一致，GRPO 类组相对算法尤其敏感
- **Block Efficiency (τ)**（learning）：投机解码每轮平均产出 token 数，决定验证成本能否摊薄
- **AIMD 调度**（learning）：加性增、乘性减的并发控制（TCP 拥塞控制同款），此处用于 RL rollout 的 KV 显存压力自适应
- **Palu / STAR-KV**（learning）：低秩 KV cache 压缩与自适应 rank 控制的代表方法，BELT 的主要基线
