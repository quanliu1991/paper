### 1. ⭐ Cache Engineering for Agents（upvotes: 0，10-22 已涨到 45）
- **一句话**：agent 的历史管理别在文本层动刀——直接 drop 掉不要的 KV cache，保留的原地复用，零 re-prefill
- **方法**：append/drop/repos 三个 cache 原语 + 处理「cache 状态历史依赖」的 AKV serving 引擎（扩展 radix tree + segment-batch attention）
- **结果**：tool-response rolling drop 策略下成本 −27.7%、分数 +1.7 点，P95 延迟 1.5×，输出吞吐 1.2×（vs 阈值摘要）
- **链接**：[arXiv](https://arxiv.org/abs/2610.28577) · infra 相关性: 5/5 · 子方向: kv-cache
- **精读**：[笔记](../../notes/papers/2026-10-21-cache-engineering-akv.md)

### 2. ⭐ HAWK: Heterogeneity-Aware KV Cache Transfer for GPU-NPU Phase-Disaggregated LLM Inference（upvotes: 0）
- **一句话**：GPU 干 prefill、NPU 干 decode 各展所长，难点是 KV cache 跨芯片搬家——布局感知的 RDMA buffer 让搬家开销 <1%
- **方法**：NPU 驱动加 peer memory client 打通 RDMA；每个 DRAM 通道一个 buffer 拼出目标张量布局，数据落地即用
- **结果**：与 GPU-only 系统吞吐差 <7.88%，功耗效率 1.26×、成本效率 1.72×（p150a decode 的成本效率是 A100 的 5.88×）
- **链接**：[arXiv](https://arxiv.org/abs/2610.29873) · infra 相关性: 5/5 · 子方向: serving-system
- **精读**：[笔记](../../notes/papers/2026-10-21-hawk-gpu-npu.md)

### 3. ⭐ UlaCache: Unified Logical Addressing for Sparse LLM Serving（upvotes: 0）
- **一句话**：给 GPU+CPU 的 KV 存储统一「门牌号」，稀疏注意力按门牌取件——一份历史只存一处，并发随总容量扩展
- **方法**：统一逻辑地址空间（TP 下 8 卡聚合，顺手解决 MLA 87.5% 的 TP 复制）+ PB-LRU 并行桶式替换
- **结果**：GLM-5.3@8×B300 开投机解码，峰值 decode 吞吐 vs HiSparse：DP 1.73× / TP 2.51×；不开投机 TP 达 SGLang 3.51×
- **链接**：[arXiv](https://arxiv.org/abs/2610.29820) · infra 相关性: 5/5 · 子方向: kv-cache
- **精读**：[笔记](../../notes/papers/2026-10-21-ulacache.md)

### 4. ⭐ Specter: Fast MoE Inference via Quantization-Enabled Multi-Step Speculative Offloading（upvotes: 20）
- **一句话**：MoE 单卡放不下、expert 搬家卡 PCIe——用量化 draft 模型提前看几步，预知要哪些 expert 提前搬
- **方法**：量化 drafter 保真 expert 激活模式，多步 lookahead 驱动 expert 预取与执行重排
- **结果**：单请求 TPOT 平均 1.50×（最高 1.88×）vs SOTA offloading 系统
- **链接**：[arXiv](https://arxiv.org/abs/2511.14102) · infra 相关性: 5/5 · 子方向: moe-inference

### 5. ⭐ TeCoP: Accelerating dLLM Decoding via Tentative Context Pipelining（upvotes: 0）
- **一句话**：扩散语言模型的解码反复重算已稳定的预测——把「预测可用性」和「当上下文用」解耦，稳定未提交的预测先当临时上下文用起来
- **方法**：交错块并行流水 + draft-and-verify，置信度与稳定性检查把关提交
- **结果**：LLaDA/Dream 上前向评估次数 −87%，吞吐 7.50×（无 KV cache）/ 11.77×（有 cache）
- **链接**：[arXiv](https://arxiv.org/abs/2610.27583) · infra 相关性: 5/5 · 子方向: speculative-decoding

### 6. ⭐ Lafa: Large Flow Language Models（upvotes: 11）
- **一句话**：连续 flow 语言模型做到 8B——前缀因果注意力 + 块内双向异步 flow，AR 预训练权重直接改造，8B 只用 <30B token 训出来
- **方法**：flow 训练保留甚至提升 AR 能力（多 token 预测效应），自投机解码用 AR 验证 flow 草稿
- **结果**：单模型内 flow-draft + AR-verify 吞吐 2.54×，质量与 AR 持平，胜过 MTP 与离散扩散
- **链接**：[arXiv](https://arxiv.org/abs/2610.28559) · infra 相关性: 4/5 · 子方向: speculative-decoding

### 7. ⭐ ProVe: Proposer-Verifier Decoding（upvotes: 0）
- **一句话**：投机解码角色反转——大模型一次前向直接提出整块未来 token，小模型来验证
- **方法**：AR checkpoint 微调成块预测 proposer（block 16 时平均 AR 前缀 6.6 token）；proposer 自验证即无损版
- **结果**：32B proposer 无损 2.5× AR 吞吐（不用训 draft head）；3B verifier 版 2.7× 换 2.6 点精度
- **链接**：[arXiv](https://arxiv.org/abs/2610.27815) · infra 相关性: 5/5 · 子方向: speculative-decoding

### 8. ⭐ Stratified Sparse Attention（upvotes: 0）
- **一句话**：极稀疏下 top-k 捡漏、纯采样方差大——确定性检索 + 分数引导采样 + 包含概率校正，把稀疏到稠密的差距压到 6-15%
- **方法**：SSA 统一框架，top-k/top-p/混合都是特例；proxy 分数给残差采样加权
- **结果**：RULER-HARD 128K@50× 稀疏恢复稠密 85% 精度；优化 kernel 下 1M 上下文 decode 2.96× 于 FlashInfer
- **链接**：[arXiv](https://arxiv.org/abs/2610.28441) · infra 相关性: 4/5 · 子方向: long-context-vlm

### 9. ⭐ RACE: RoPE-Aligned Attention Compression（upvotes: 0）
- **一句话**：head 维压缩 KV cache 却要在推理时重建全维表示？按「完整旋转对」选坐标，压完的权重直接折叠、免重建免专用 kernel
- **方法**：query-key 联合激活能挑选 rotary pair（RoPE 兼容的充要条件是整对保留），校准集后训练
- **结果**：KV 保留 50% @256K 上下文：总 FLOPs −47.8%、吞吐 1.79×、TTFT −43.2%、显存 −28.1%
- **链接**：[arXiv](https://arxiv.org/abs/2610.28385) · infra 相关性: 4/5 · 子方向: kv-cache

### 10. ⭐ RISK-KV: Quality-Aware Selective KV Cache Reconstruction（upvotes: 0）
- **一句话**：分布式推理的请求迁移/恢复要带全量历史 KV 太重——两边夹着的目标层可以用岭回归「算」出来，省掉 18-33% 的 KV 传输
- **方法**：跨层 ridge 回归预测缺失层输入，折叠原模型 KV 投影矩阵省存储；NLL 变化做质量门控选层组
- **结果**：省 18.2-33.3% 历史 KV、困惑度变化 <0.5%；512-token 历史恢复比全量 Token Replay 快 1.51-3.31×
- **链接**：[arXiv](https://arxiv.org/abs/2610.29544) · infra 相关性: 5/5 · 子方向: kv-cache

### 11. ⭐ RCSD: Reinforcement and Continual Learning for Domain-Specific Speculative Decoding（upvotes: 0）
- **一句话**：draft 模型蒸馏学的是 target 的全分布（包括高熵乱区）——改用推理时自然产生的接受/拒绝序列构造偏好对做 RL
- **方法**：接受长度最大化的系统级目标 + masked loss 不罚 target 对齐 token

- **链接**：[arXiv](https://arxiv.org/abs/2610.29527) · infra 相关性: 5/5 · 子方向: speculative-decoding

### 12. ⭐ FrameBlend: Cache Locally, Recompute Selectively for Streaming Video Understanding（upvotes: 0）
- **一句话**：流式视频理解的空闲期 prefill 上下文受限导致「上下文错配」——查询时挑关键视频 token 用查询相关上下文重算 KV
- **方法**：即插即用的选择性 KV 重算，空闲期注意力窗口因此可以开短
- **结果**：五个基准精度最高 +3.9pp；RVS-Ego 每帧 prefill FLOPs −20%+，总处理时间 −14-59%

### 13. ⭐ OrbitWeaver: Resuming Vision-Language Inference across Onboard Interruptions（upvotes: 0）
- **一句话**：卫星上的 VLM 推理会被断电/重启打断，重启就丢 KV 重头再来——按视觉编码/prefill/decode 三阶段寿命选检查点边界
- **方法**：phase-aware checkpointing + 依赖感知动态恢复（层×token 块两维调度），检查点读写与重算重叠
- **结果**：真实在轨遥测负载下端到端 4.07× 加速，SSD 写量 −3.56×；两颗低轨卫星 72 小时部署验证
- **链接**：[arXiv](https://arxiv.org/abs/2610.29183) · infra 相关性: 4/5 · 子方向: serving-system

### 14. ⭐ Is 2:4 Sparsity Still Worth It?（upvotes: 0）
- **一句话**：同 bit 预算下「加 2:4 稀疏」几乎总是不如「再降一档精度」——2:4 丢掉的能量不随 bit 数缩小，量化误差却会缩
- **方法**：三代 GPU、transformer 全部六种 GEMM 操作数、等 bit 等档位的系统对比（含在线剪枝+量化）
- **结果**：降到硬件最低精度后 2:4 仍有 1.3-1.7× 线性层加速；H100 上重训练 2:4 FP8 vLLM prefill 吞吐 +27%——但质量要靠重训练赢回来，FP4 的 Blackwell 稀疏没救回来
- **链接**：[arXiv](https://arxiv.org/abs/2610.28947) · infra 相关性: 4/5 · 子方向: quantization-compression

### 15. ⭐ The Token-Energy Law of LLM Decode（upvotes: 0）
- **一句话**：每生成一个 token 耗多少焦耳？一个仿射模型说清楚：活动字节数（权重+KV）× 实际 decode 时间，预测误差 <3.73%
- **方法**：active bytes 拆「批内共享的稠密权重读」与「每请求私有的 KV 读」，与时间坐标做仿射组合，按模型×硬件标定系数
- **结果**：Hopper/Blackwell + TP2 上三模型验证，held-out 条件均值误差 ≤3.73%——部署侧能耗建模有了简洁公式
- **链接**：[arXiv](https://arxiv.org/abs/2610.28576) · infra 相关性: 4/5 · 子方向: serving-system

## 📖 今日新词
- **Cache Engineering（cache 工程）**：在 KV cache 层直接增删/重定位而非改写文本历史——避免 re-prefill，代价是 cache 状态变成历史依赖（learning）
- **History Dependence（cache 状态历史依赖）**：同样的 token 前缀在不同 cache 操作序列下产生不同 KV 状态——前缀匹配复用会出错，需要把操作历史编进 radix tree（learning）
- **Segment-batch Attention（分段批量注意力）**：恢复缺失 KV 时按 drop/repos 边界把 query 切段、各段用各自可见性，一次前向恢复全部状态（learning）
- **统一逻辑地址空间（Unified Logical Addressing）**：GPU 与 CPU 的 KV 存储共用一套稳定逻辑地址，数据搬家只改映射不改地址——引擎与物理布局解耦（learning）
- **PB-LRU（并行桶式 LRU）**：GPU 槽按「最近访问轮次」分桶（bitmap 表示），并行更新 recency、层级摘要选淘汰对象，避免全池扫描（learning）
- **MLA TP 复制（MLA Replication）**：MLA 的 KV 是全头共享压缩表示，head 切分的张量并行切不开它——每卡一份完整副本，8 卡 TP 时 87.5% 分配是冗余（learning）
- **Peer Memory Client**：把设备内存暴露给 RDMA 子系统的驱动组件（NVIDIA 有现成的 nvidia-peermem，NPU 要自己写），NIC 因此能直访显存不走 host（learning）
- **GEMV 瓶颈**：decode 阶段逐 token 的矩阵向量乘——tile 并行度低、数据复用少，GPU tensor core 利用率从 prefill 的 ~93% 掉到 ~36% 而功耗不变（learning）
- **D-PAL（分布级接受损失）**：draft 训练用接受概率=分布重叠度（1−TV 距离）做逐位权重，Rényi-1/2 损失上下界夹住真实接受率（learning）
- **Token-Energy Law**：每 token 能耗的仿射模型——活动字节数（共享权重+私有 KV）与实际 decode 时间的线性组合，预测误差 <3.73%（learning）
