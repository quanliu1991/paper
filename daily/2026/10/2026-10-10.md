## 🚀 推理 Infra（6 篇）

### 1. ⭐ Taking Tokenization off the Host for Agentic LLM Serving（upvotes: 0）
- **一句话**：agent 应用反复重发超长上下文，prefix caching 省掉了重复计算，但 tokenization 这个 CPU 环节成了新瓶颈——这篇把它整个搬到 GPU 上，首 token 延迟降一半多。
- **方法**：GraphTok，把从预分词、BPE 合并到 token ID 拼装的整条 tokenizer 流水线做成一个可重放的 CUDA Graph，bit 级复现 GPT-2/Llama 3/Qwen 2.5/DeepSeek-V3/Gemma 3 的结果；短输入仍走 CPU，即插即用接入 vLLM 和 NVIDIA Dynamo。
- **结果**：100 万 GPT-2 token 编码 1.7–3.2ms；比最强的 CPU tokenizer gigatoken 快 4.7–6.0x；vLLM 缓存命中场景平均 TTFT（首 token 延迟）降 2.1–2.4x；同样 2 秒 P99 目标下，一个 Dynamo 前端撑起 518 请求/秒的 121K token 流量——相当于 56 张 GPU 最忙小时的负载（默认 tokenizer 只能撑 18.5）。
- **链接**：[arXiv](https://arxiv.org/abs/2610.13325) · infra 相关性: 5/5 · 子方向: serving-system

### 2. ⭐ KV-Repurpose: A Testbed for Evaluating Non-Prefix KV-Cache Reuse（upvotes: 0）
- **一句话**：现在的 KV cache 复用只认「一模一样的前缀」，同一篇检索文档换个 system prompt 就全废——这篇开源了一个 vLLM 版试验台，专门研究「不连续前缀」的 KV 复用。
- **方法**：开源系统 KV-Repurpose：cache 感知的段调度 + prompt 构造 + 容量管理 + 负载生成 + 运行时监控，支持在段粒度上开发与评测非前缀 KV 复用策略。
- **结果**：Zipfian RAG 负载下（20% 请求共享固定前缀），同样 30GB 缓存，段级复用命中率 63.9% vs prefix caching 的 3.3%；prefix caching 堆到 1TB 缓存也只到 17.9%。
- **链接**：[arXiv](https://arxiv.org/abs/2610.13060) · infra 相关性: 5/5 · 子方向: kv-cache

### 3. ⭐ S$^3$R: Fast and Faithful RL Rollouts via Self-Sparse Speculative Decoding（upvotes: 0）
- **一句话**：RL 训练里 rollout（用当前策略生成推理轨迹）占了大头时间，直接用稀疏注意力采样会改变训练所依赖的分布——这篇让稀疏注意力只负责「起草」、完整注意力负责「验证」，速度上去了还不破坏训练稳定性。
- **方法**：Self-Sparse Speculative Rollouts：稀疏注意力提出 token + 全注意力验证 + 精确投机采样，起草验证共享同一套策略参数（不用单独训 drafter）；配 KV-aware 调度器限制 KV cache 反复 offload/恢复。
- **结果**：Qwen3 长上下文数学推理任务，端到端训练吞吐 1.35–1.39x，任务表现持平。
- **链接**：[arXiv](https://arxiv.org/abs/2610.13202) · infra 相关性: 5/5 · 子方向: speculative-decoding

### 4. ⭐ Surfing the Activation Wave: Analyzing the Information and Geometry of LLM Hidden States for Speculative Decoding（upvotes: 0）
- **一句话**：投机解码的 draft model 从大模型哪几层取特征一直靠拍脑袋定（默认取第 2、中间、倒数第 3 层），这篇用信息论工具给出了有原则的选层方法。
- **方法**：用 matrix-entropy 衡量「信息量」、CKA 衡量「冗余度」，配 token-entropy 过滤（剔除低预测熵 token 的 hidden states）做层选择；在 EAGLE3 式投机解码上验证。
- **结果**：选出的层集合优于固定默认规则（[2, N//2, N-3]），并解释了为什么某些默认选择碰巧能打。
- **链接**：[arXiv](https://arxiv.org/abs/2610.12939) · infra 相关性: 4/5 · 子方向: speculative-decoding

### 5. ⭐ DP-MIND: Differentially private memory-guided Long context Inference（upvotes: 0）
- **一句话**：百万 token 级的敏感长文本想发给云端大模型又不泄露隐私——这篇用「本地小记忆 + 差分隐私扰动」的分块处理方式做到了。
- **方法**：DP-MIND：输入先本地加噪，分块处理时用一个紧凑 memory 跨块保留任务相关信息（memory 构造策略用 RL 在扰动输入上直接优化），答案中被噪声破坏的片段由本地去噪模块恢复。
- **结果**：百万 token 级长上下文基准上，可扩展性与效用全面超过现有 DP 推理与长上下文基线。
- **链接**：[arXiv](https://arxiv.org/abs/2610.13132) · infra 相关性: 3/5 · 子方向: long-context-vlm

### 6. ⭐ Overcoming Data Imbalances with Expert Selection Biases（upvotes: 0）
- **一句话**：MoE 预训练里低资源类别（小语种/稀有模态）被挤到角落没容量——给路由器加个「按类别偏置」的小旋钮，小语种也能分到足够的专家容量，推理方式不变。
- **方法**：category-conditioned expert-selection bias：在路由打分时按输入类别加偏置，诱导软性的类别-专家对齐，保留跨类别共享；推理时保持标准 MoE 路由。
- **结果**：多模态、低资源语言、代码任务上，最大 10.6B 模型都有提升；折算成等效训练 token，小/大规模分别相当于多喂了 18.5% / 2.7% 的数据。
- **链接**：[arXiv](https://arxiv.org/abs/2610.13370) · infra 相关性: 3/5 · 子方向: moe-inference

## 📖 今日新词
- **GraphTok**（learning）：整条 tokenizer 流水线跑成单个 CUDA Graph 的 GPU 分词器
- **TTFT**（unknown）：Time To First Token，首 token 延迟，主要由 prefill 决定
- **matrix-entropy**（learning）：衡量表示「信息量」的矩阵熵分析工具，用于挑投机解码的特征层
- **CKA**（learning）：centered kernel alignment，衡量两组表示相似度/冗余度的常用指标
